# POAM — Clyffy Avatar Plan of Action & Milestones

**Purpose:** the sequenced, followable plan from the current verified baseline to a fully built
avatar. I FOLLOW this — one milestone at a time, foundation-first, with a proof gate before
moving on. It is the anti-drift + anti-reward-hack mechanism for this pack.

**How to use it:** each milestone has a **VERIFY gate** — it is not done until the evidence is
shown AND the operator confirms. Status vocabulary matches `clyffy/docs/DECISIONS.md`:
**SPEC** (decided) → **BUILT** (produces artifacts) → **VERIFIED** (proven + operator confirms).

**Golden rule:** never advance to the next milestone until the current one is **VERIFIED**.

**Pairing:** this file is the ONE **build plan** (sequenced milestones). `STATUS.md` is the
current-truth resume point, `BUILD_LOG.md` is the chronological record of what was measured
and why, `clyffy.pack.toml` is the SSOT for values. Milestones live here; running state lives
in `STATUS.md`. Journal against this file in `/home/hades/Projects/clyffy/JOURNAL.md` — one
entry per milestone attempt, **including the ones that fail**.

**Governing law (from `CLAUDE.md`):** no reward-hacking, no minimal-fix-to-green, no hidden
warnings. A rejected approach is recorded with its numbers, not silently dropped. Three
approaches were rejected on evidence in this pack already (displacement relaxation, eyelid
densification, two posed-containment tests) — that is the standard, not an exception.
